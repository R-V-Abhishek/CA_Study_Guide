## Operations

The additive migration is `0008_baseline_adoption`. Back up before adopting a persistent database. Preparation and activation are separate transactions; failures roll back the whole operation. Repeated identical preparation/activation is idempotent, while conflicting input hashes stop the operation.

```sh
uv run caf baseline prepare
uv run caf baseline activate c59e12cb4f9696adbcc4647b0775542693517aa23870e37edfca753497370973
uv run scripts/verify_baseline.py
```

The default actor is administrator account 1; the database operation checks that the actor is active and an administrator. Authenticated HTTP administration is available through `GET /api/v1/curate/baselines`, `POST /api/v1/curate/baselines/prepare`, and `POST /api/v1/curate/baselines/{release_id}/activate` with `{"manifest_hash":"…"}`. Normal correction, dispute, verification and revision-conflict controls remain in place.

For rollback, the CLI `caf baseline rollback <manifest_hash>` and administrator-only `POST /api/v1/curate/baselines/{release_id}/rollback` restore the previous release/binding and publication pointers only where the baseline pointer is still current. Later corrections, personal notes/progress and all immutable history remain stored. A committed rollback requires a new explicit adoption before reactivation; retries cannot silently republish a retired baseline. `verify_baseline.py` exercises rollback in a transaction that it discards, leaving the accepted release active.

The actual pre-adoption backup is under `data/backups/pre-baseline-2026-10-16/caf_20261016_172904_002212_a19cd0fb/`. An independent disposable restore verified every one of its 74 table digests, archived files and schema. The retired disposable preview, including its personal records, was separately preserved under `data/backups/retired-preview-2026-10-16/` before shutdown.

## Local application and limits

The ordinary persistent application runs at `http://127.0.0.1:8788` with Auth0. Port 8000's unrelated service is preserved. No acceptance landing page, account switches, banner or local experience sign-off is required.

Native-browser inspection confirmed the ordinary sign-in page. Auth0 discovery currently fails before provider redirect because the host cannot resolve the OIDC metadata address (`httpx.ConnectError`, errno 8). Provider allowlists and authenticated browser journeys therefore remain unverified. Chromium/WebKit automated launches are also blocked by this environment's browser startup errors. These are not evidence that production authentication or cloud deployment is complete.

The current local dependency environment runs with `uv run --no-sync`; dependency synchronization was attempted but PyPI DNS prevented fetching the existing setuptools build requirement. The installed environment passed the relevant Python suites. Docker test/restore host ports required temporary forwards through the existing Colima SSH connection; no persistent Docker configuration was changed.
