# Phase 7 student usability pilot

Status: **not conducted**. Automated browser fixtures verify implementation; they do not provide observations from invited students. This gate must be completed before Phase 8.

Use actual invited accounts and reviewed content when available. If the live corpus is still unpublished, record that dependency and use explicitly labelled isolated fixtures for interface observations without creating live approvals.

Ask each participant to complete these tasks without developer explanation:

1. Open Today, select a paper and find a syllabus topic. Return to Today and resume it.
2. Find a previous question using search and filters. Read its shared case and every part, reveal its answer and inspect the cited original page. Return with the same filters and selected row.
3. Write a note, save it, edit it again and navigate away. Explain the displayed save state and choose a deliberate exit action.
4. Record personal progress, inspect the resulting plan, then navigate the revision queue without recording an outcome accidentally.
5. Review the complete question, available answer and all labels. Explain the difference between publishing a review, verifying current labels and submitting a correction. Check a blocker or conflict before any live attestation.
6. Repeat the reading and note tasks on a phone or at 200% zoom using labelled navigation and keyboard controls.

For each session, record participant identifier, account role, device/viewport, theme, corpus context, task completion, wrong turns, requests for help, misunderstood status/action text and the participant's actual words. Do not infer understanding from clicks or manufacture quotes.
